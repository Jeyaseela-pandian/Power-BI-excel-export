Strategies, strongest first

A correct table beats a chart that only looks similar: a visual becomes an Excel chart only when the chart keeps its meaning.

NATIVE
A real Excel equivalent: an Excel chart, or an Excel Table with the report's formatting.
CONSTRUCTED
Excel has no such visual, so it is built from Excel parts that keep the meaning: tiles, sparklines, outlines, live formulas.
APPROXIMATE
The closest Excel chart keeps the numbers; the visible difference is named in this report.
TABLE
No Excel chart reads correctly (maps, trees): the data as a formatted table, in the visual's colours.
FILTER CHIP
Slicers become the filter bar: field and selection, "All" when nothing is picked.
NOT EXPORTABLE
Power BI refuses to export the visual's data: the sheet's notes name it, nothing breaks.

  • Every page replayed through the export with the rows Power BI would send; structural checks clean (headers, merges, hidden rows).
  • Both workbooks opened in desktop Excel: charts, sparklines, data bars, tables and 142 live formulas all load.
  • Sorting a table with sparklines keeps every line on its own row (checked in Excel).
  • Each page compared with Power BI Desktop side by side (separate document).

Known limits

  • Totals are filled only where adding the rows gives Power BI's total (sums, counts, min / max, additive measures); ratios, averages and distinct counts are left blank.
  • Table sparklines need permission to query the semantic model (Build); otherwise a note names them.
  • New-card reference labels appear when Power BI includes them in the export.
  • Maps, treemaps and decomposition trees are tables: Excel has no equivalent chart.
